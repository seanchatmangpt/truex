# Summary: SigSPARQL: Signals as a First-Class Citizen When Querying Knowledge Graphs

**File:** SigSPARQL- Signals as a First-Class Citizen When Querying Knowledge Graphs .pdf

## 1. Main Thesis
Monitoring Cyber-Physical Systems (CPS) requires integrating high-level semantic context (Knowledge Graphs) with low-level, high-frequency time series data from sensors. Existing observation-based approaches are cumbersome for expressing computations on sensor data due to sampling asynchronicity. SigSPARQL proposes treating **Signals** (continuous functions from time to data) as "first-class citizens" within SPARQL, enabling the declarative definition of complex monitoring logic that abstracts away the underlying data point irregularities.

## 2. Key Findings
- **Signal-Annotated RDF Datasets:** The data model associates IRIs (signal sources) with properties (signals) through an annotation function.
- **Continuous Query Framework:** SigSPARQL introduces a language-agnostic framework of three operators:
    - `Signal(s, p)`: Obtains a signal from the knowledge graph.
    - `ApplySF(f, args)`: Applies signal functions (e.g., addition, integration) to signals.
    - `LiftVal(v)`: Promotes static knowledge graph values to constant signals.
- **New Syntax Clauses:** 
    - `SIGNALS { ... }`: Used to bind variables to physical signals.
    - `WHEN { ... }`: Defines a predicate (e.g., `SUM(?ap) > ?env`) that triggers a continuous event when it becomes true (positive edge).
- **Temporal Solution Sequences (TSS):** The query result is a solution sequence where variables can be bound to signals, allowing the result set itself to be evaluated at any time point τ.
- **Abstraction over Observations:** Signals solve problems like asynchronous sampling and irregular rates by providing a "held" or interpolated value between observations.

## 3. Truex Grammar of Consequence Analysis

### Substrate (The Cyber-Physical System)
The substrate is the physical CPS (e.g., an EV charging garage) consisting of sensors, actuators, and power flows. It represents the "Pre-Gall" physical state where raw sensor observations are emitted as a high-entropy stream.

### Membrane (The SigSPARQL Query)
A SigSPARQL query acts as an **Active Computational Membrane**. It encapsulates the physical substrate and defines the "Law of Behavior" (e.g., "The total power shall not exceed the envelope"). The query intercepts raw signals and filters them through semantic rules.

### Attempt (The Signal State Transition)
Every change in sensor data (e.g., a charger increasing its power draw) is an **Attempt** to transition the system's state.

### Admit / Refuse (The WHEN Clause)
The `WHEN` clause serves as the **Admission Controller**. As long as the signal predicate remains false, the system state transitions are "internally" processed. When the predicate (the law) is violated (e.g., `Power > Limit`), the membrane **Admits** the transition as a significant event and triggers a consequence.

### Receipt (The Triggered Triples)
The **Receipt** is the set of triples generated by the `CONSTRUCT` clause when a trigger event occurs. These triples (e.g., `?garage hasViolation [ ... ]`) provide a deterministic, cryptographically-scopable (via blank nodes) record of the law violation and the resulting system state.

## 4. Relevance to Truex Post-Gall Operating Substrate
The Truex substrate is designed to bridge the gap between logical laws and physical reality. SigSPARQL provides the **Mathematical Language of Consequence** for the physical world. It allows the Truex substrate to treat physical sensors as "Physical Invariants" and to mechanically enforce "Behavioral Laws" across distributed cyber-physical environments. By converting high-entropy sensor streams into low-entropy, deterministic events, SigSPARQL enables the creation of an **Active Law Enforcement Layer** that operates at the speed of the physical substrate.
