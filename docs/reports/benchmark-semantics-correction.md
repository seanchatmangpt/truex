# Benchmark Semantics Correction Report

## Terminology Review & Naming Corrections

In previous iterations, the phrase **"Million Hooks"** was loosely used to describe high-throughput execution runs. To ensure absolute compliance with Gall's Law and truth-in-advertising standards, we have corrected all benchmark terminology:

*   **Misleading Naming:** "1,000,000 unique hooks registered" (implies registering a million distinct hook function instances concurrently, which is memory-prohibitive and structurally unnecessary for realistic validation).
*   **Corrected Naming:** **"1,000,000 Hook-Delta Evaluations"**. The benchmark achieves this target via a cross-evaluation of **1,000 registered hooks** against **1,000 processed deltas** (evaluations = hooks $\times$ deltas).

## Distinct Definitions

The benchmark now explicitly defines and prints separate metrics for:
1.  **Hooks Registered (`registeredHooks`):** The size of the active policy field.
2.  **Deltas Processed (`processedDeltas`):** The number of individual GraphDelta events sent through the engine.
3.  **Total Hook-Delta Evaluations (`totalHookDeltaEvaluations`):** The total combinatorial number of checks performed ($Hooks \times Deltas$).
4.  **Matched Hooks (`matchedHooksCount`):** The number of times a hook predicate matched a delta predicate and executed.
5.  **Emitted Effects (`effectsCount`):** The count of side-effects generated by matching executions.
6.  **Receipts Generated (`receiptsCount`):** The count of ML-DSA signed execution proofs.
7.  **Evaluation-Only (`evalOnly`):** A mode that skips receipt generation to isolate and measure pure pattern-matching logic.
8.  **Receipt-Backed (`receiptBacked`):** A mode that includes cryptographic receipt signing and verification overhead.

The benchmark now distinguishes hooks from hook-delta evaluations.
