### Transactional Atomicity Property Fix
During execution, we observed the following property test failure:
```
 FAIL  packages/truex-core/test/membrane.test.ts > ... ensures transactional atomicity: all operations roll back on failure
Counterexample: [{__proto__:null},[{"key":"toString","value":false}]]
```
* **Root Cause:** The property test cloned the random `initialTarget` object generated by fast-check using the object spread operator (`const target = { ...initialTarget };`). However, `initialTarget` was generated with a null prototype. Standard object spread (`{ ... }`) in JavaScript constructs an ordinary object with `Object.prototype`. The cloned object inherits prototype properties like `toString`, so `toString in target` evaluates to `true`. When rollback ran, it deleted mutated properties, but `toString in target` remained `true` (inherited), whereas `"toString" in initialTarget` was `false`, causing the assertion `expect(key in initialTarget).toBe(true)` to fail.
* **Fix Applied:** Modified [packages/truex-core/test/membrane.test.ts](file:///Users/sac/truex/packages/truex-core/test/membrane.test.ts#L74-L115) to preserve the original prototype during target cloning:
```typescript
const clone = (obj: any) => {
  const c = Object.create(Object.getPrototypeOf(obj));
  return Object.assign(c, obj);
};
const target = clone(initialTarget);
```
