## 2. ORIGINAL PURPOSE
Databases store current state but overwrite history. Git stores history but is optimized for source code, not application state. `gitvan` was built to bridge this gap, treating the Git protocol as a substrate for storing high-frequency snapshots and operational trajectories. It was stress-tested against "one million breaking points" and "dark matter workloads" to see if Git could handle enterprise-scale object-centric event logging.
